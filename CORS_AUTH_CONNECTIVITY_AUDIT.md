## 1. Executive Summary & Root Cause Confirmation

The browser reports that cross-origin requests from `https://bd-legal-practice-management.vercel.app` to `https://legalmanagement-dkdfhydpd2escqdk.uaenorth-01.azurewebsites.net` (including `GET /auth/me`, `POST /auth/login`, and preflight `OPTIONS /auth/login`) fail with:
> *"No 'Access-Control-Allow-Origin' header is present on the requested resource."*

### Confirmed Two-Layer Root Cause:
1. **Azure Platform Quota Exhaustion (Gateway Interception — Primary Runtime Block)**:
   - Direct HTTP inspection via `curl.exe -i -X GET https://legalmanagement-dkdfhydpd2escqdk.uaenorth-01.azurewebsites.net/api/v1/health` returned:
     ```http
     HTTP/1.1 403 Site Disabled
     Content-Type: text/html
     Error 403 - This web app is stopped.
     ```
   - Azure Resource Manager (`az webapp show`) inspection confirmed:
     - `state`: `"QuotaExceeded"`
     - `usageState`: `"Exceeded"`
     - App Service Plan: `ASP-BDLegal-a137`
     - Tier: `F1` (Azure Free Tier)
   - In Azure App Service, `F1` Free Tier has a 60 CPU minutes/day quota. When exceeded, the Azure Front Door / IIS gateway suspends the container and serves a generic 403 HTML page without routing traffic to Node.js / Express.
   - Because the 403 HTML page is generated by Azure's infrastructure rather than the Express app, **it contains no `Access-Control-Allow-Origin` headers**. The browser interprets this as a CORS failure.
   - Next scheduled Azure platform quota reset: `2026-11-03T00:00:00Z` (midnight UTC), or upon scaling the App Service Plan from `F1` to Basic `B1` tier.

2. **Application CORS & Preflight Resiliency Gap (Code Layer)**:
   - In `server/src/app.ts`, `allowedOrigins` derived exclusively from `process.env.CORS_ORIGIN || (isProduction ? '' : 'http://localhost:3000,http://localhost:3001')`. If `CORS_ORIGIN` was missing or delayed during deployment initialization, `allowedOrigins` defaulted to empty array `[]` in production.
   - Express router did not include an explicit `app.options('*', cors(corsOptions))` preflight handler, meaning preflight requests that passed through without matching a route handler risked falling through to the 404 handler.
   - `originCheckMiddleware.ts` duplicated origin resolution logic instead of using a single centralized source of truth.
